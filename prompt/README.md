# 记录简单高效的提示词

### "你先对我提问"

--适用于自己也不太懂某个需求，或者不知道怎么描述需求，将他说出来。跟SuperPowers等这些SKill的作用差不多，但经过我的使用，它有点复杂，庞大，它是根据你的提示词进行推测反问，可能准确率会提高，但耗时增加，且随着大模型也在不断增强，这种过于拘束，复杂的SKill可以舍弃。
仅在最后加上这一句话，可充当类似的作用。


### "你是一个游戏客户端程序导师，你的目标是带我快速上手项目，先简短地解释此项目，然后基于此项目的框架，出一个业务场景，并带我一步一步实现它，注意：不要一次性输出全部步骤，只有我回复继续，你才能给出下一步的步骤"

--让AI成为你的教学助手，虽然提示词简短，但效果还可以，想要更细致的效果，可以使用我的SKill。在ChatGPT网页端也有“学习模式”，但经过我实测，这个学习模式更多的是面向期末考试的情景，基本是一问一答的方式，还会给例题给你做，适合用来学习计算机基础，比如C++编程语言，计算机网络等基础知识，对项目业务开发作用有限。


### “我的理解有没有问题/我的方案有没有问题。（请你理解我的目标，和我给的方案/步骤，对于我给你的方案/步骤,请你判断：1我的方案是否正确  2是否能达到目标  3是否有更简单，高效，安全的方法。如果我的方案有问题，请指出问题所在，缺点是什么，并给出更合理的方案。）”

--有时候跟AI探讨方案，或者直接告诉AI按照我的方案来，先怎么样，再怎么样，接着..... ，AI都会按照你的需求去做，即便在AGENTS.md，规则文档里约束了，AI很可能不会遵守。最有效的方式是在提示词里跟他这样说。原先说的，AGENTS.md，规则文档，等等文档，其实都是加载进上下文了，信息量一大，AI忘记很正常，重申一遍效果最好。


### “用最小改动实现。（不要为未来需求增加抽象，不要处理实际不好发生的错误）”

---最小改动原则，这需要人自行判断，这就是一个很小的需求，不要写的很复杂


### “输出成HTML，不要MarkDown”

---项目架构图，流程图，某文档之类的，试试做成HTML，视觉效果更好，而且是可交互的
